# 产品定义

把明确选择的本机资料连接成可追溯知识，再将本人确认的行动与实际结果连接起来。主要入口是 CLI 和 Obsidian，真实工作区与公共工具分开。

## 用户旅程

离线试用 → 检查就绪 → 选择来源 → 增量整理 → 查回证据 → 确认行动 → 记录结果 → 复盘。

每步应说明读了什么、使用哪种整理方式、保存到哪里、是否发送到网络，以及失败后的下一步。

## 三轮交付门槛

| 轮次 | 用户阻碍 | 验收 |
| --- | --- | --- |
| 1：首次使用可验证 | 未准备私人资料就要理解全部设置 | 新目录离线演示；不调用模型/网络；重复不覆盖；只读诊断给出阻碍和修复步骤 |
| 2：日常知识可使用 | 查找、出处与行动结果脱节 | 中文/空格/相对链接资料可回溯；搜索解释命中与整理方式；旧日期窗口不泄漏后来结果；完成任务带实际结果进入复盘 |
| 3：长期运行可托付 | 故障或迁移时无法判断保存和恢复状态 | 最近尝试与成功分离；一致性备份可恢复到新目录；回填/承诺/事件保持；损坏包和覆盖操作在写入前拒绝 |

每轮有实际修改、跨角色评审和真实 CLI 旅程，最终通过跨平台 CI。[迭代记录](iterations.md) · [验证记录](validation.md)。

## 信任边界

- 本地摘录、AI 归纳、作者观点、本人承诺和实际结果分别标明。
- 未记录表示未知，复盘提示针对具体事件，不做人格评价。
- 普通同步、外部模型处理、GitHub 发布和 Magpie 传输各自配置与验证。
- 调度文件生成、系统注册、实际运行成功分别报告。
- 来源只读；真实数据不进入公共示例；恢复不覆盖现有工作区。

先完成这条旅程，不扩展为全网资讯、交易、私人社群抓取或心理诊断系统，也不先堆向量数据库、分布式服务或复杂 Agent 编排。
