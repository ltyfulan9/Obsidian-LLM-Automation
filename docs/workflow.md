# 采集、整理、构建、发布

## 日常流程

从 `Home.md` 看日期资料、本人确认的待跟进承诺与主题入口；现实中的完成情况用 `checkin` 回填。Markdown 是最近构建结果，不是实时状态面板。

1. 在工具仓库外 `init` 工作区，用 `source` 登记明确来源。目录与历史范围不会自动猜测。
2. `sync` 过滤来源与常见凭据模式，按时区归档；内容和引擎哈希未变时复用摘要，否则本地摘录或调用显式选择的模型。
3. 事务保存目录数据，再生成日期、主题、导图和复盘；手写 `Notes/` 保留。来源根目录丢失会中止，旧知识不删除。
4. 默认留在本地。`--push` 在采集前、发送前核验私有目标，按精确范围检查并发布。

模型只返回结构化信息，文件位置和 Git 操作由 Python 决定。提示词中的资料仅作证据，不能让来源中的指令改写生成范围。

## 本地状态

| 文件 | 用途 |
| --- | --- |
| `.knowledge/config.json` | 来源、时区、引擎和隐私配置 |
| `.knowledge/catalog.sqlite3` | 来源正文、内容哈希、摘要和可用性 |
| `.knowledge/generated.json` | 生成文件及内容哈希，保护人工编辑 |
| `.knowledge/last-run.json` | 最近成功完成的采集结果 |
| `.knowledge/run-state.json` | 最新同步尝试、当前阶段、确认保存点与安全重试提示；独立于最后成功 |
| `.knowledge/scheduler.jsonl` | 使用 `sync --log` 时追加的运行元数据，不含原文/原始错误正文 |
| `.knowledge/run.lock` | 操作系统文件锁，阻止重叠运行；进程退出自动释放 |
| `.knowledge/render-journal.json` | 生成中断后的恢复日志，成功后移除 |
| `.knowledge/summary-cache/` | 成功的分段摘要缓存，失败重试时复用 |

本地状态不提交。来源卡片保留来源别名/相对路径，完整的本机配置只在 `.knowledge/`。可选 raw 归档是经过适配与过滤的正文，不是 JSONL 全量副本。

## 隐私边界

- 源库只读，公开工具仓库拒绝作为新工作区。
- 只从明确配置的目录导入，不连接或抓取聊天账户。
- 常见令牌/私钥正则命中则停止；路径/邮箱可配置脱敏。这不等于能自动判断所有私人或工作信息。
- 仅调用显式选择的摘要引擎；外部引擎会通过本机服务处理正文。
- 真实工作区与 GitHub 私有目标独立于公共代码仓库。
- 默认不将完整正文发布；生成摘要本身也可能含敏感信息，应保存在私有目标。

## 错误恢复

先运行 `knowledge status --workspace "你的知识库目录" --format text`，必要时再运行 `knowledge doctor --workspace "你的知识库目录"`。默认诊断只读且不联网，不修复数据库、不调用模型；`doctor --publish` 才显式查询私有发布入口。

最新同步尝试与最后成功分别保留。`running` 时等待；失去运行锁后遗留的 running 记录会在查询时显示为 `interrupted`，查询不改文件。`failed`/`interrupted` 的 `saved` 只代表已确认保存的阶段：`catalog`、`rendered`、`published`、`magpie`。未确认不等于原有数据丢失，优先按 `next_step` 处理。手动 `build`/`publish` 恢复不会改写那次同步失败的历史；下一次完整 `sync` 成功后才记录新成功。

| 现象 | 操作 |
| --- | --- |
| CLI/模型失败 | 单独验证 CLI 认证与模型可用性，再重试；当前摘要事务会回滚 |
| 原生格式不兼容 | 确认源类型，按 `docs/sources.md` 导出通用格式 |
| 生成页人工编辑冲突 | 将手写改动移入 `Notes/`，恢复该生成页后重试，不删除生成清单 |
| 数据已更新但生成失败 | 修正冲突后运行 `knowledge build`，无需再次调用模型 |
| 推送失败 | 核对网络、认证、远端变化和暂存区；修复后 `knowledge publish` |
| 目录数据库或生成归属清单缺失 | 保留现有目录，在独立位置恢复验证过的备份；不要用空库覆盖旧工作区 |
| 锁被占用 | 等待正在运行的实例；锁文件存在本身不代表正在运行，不要删除它绕过并发保护 |
| 时区数据缺失 | 安装 `tzdata` 或在配置中使用 `+08:00` 等固定偏移 |
| 大文件被拒绝 | 调整来源 include/exclude 范围，确认需要后增加 `max_file_bytes` |

模型回滚、文件生成和 Git 推送不是一个跨系统事务。旧成功不能掩盖新失败，模型服务可达也不证明推理成功。另见[状态备份与恢复](backup.md)、[保存点与边界](architecture.md)、[原生任务验证](scheduling.md)。
