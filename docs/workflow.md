# 自动维护流程

## 1. 配置与私有目标检查

运行器读取 `.local-state/config.json`，其中只有 `sourceVault`、`backupVault`、`codexBin`、`gitBin` 四个绝对路径字段。源库严格只读；全部变更写入私有备份库。

运行前检查路径和目录锁，再读取备份库的 `origin`。仅接受不带嵌入凭据的 GitHub HTTPS 或 SSH 地址，使用 `gh api` 核验仓库 `private` 为 `true`。公开、无法识别或无法核验的目标都会停止；此时不会扫描源笔记或启动 AI。

私有仓库被改为公开后，再次运行也会被拒绝。检查反映执行时的状态；应持续保持资料仓库私有。

## 2. Markdown 哈希清单

源库 `*.md` 按相对路径记录 SHA-256，与最近一次成功推送后的清单比较，得到 `new`、`modified`、`deleted`。扫描排除 `.obsidian` 和被识别为重解析点的文件。

新部署或 `-InitializeBaseline` 仅建立当前基线，不全量整理。非 Markdown 附件不会触发模型调用，但会在归档阶段同步。

备份仓库必须处于 `main` 且工作区干净。脚本不自动拉取远端、处理冲突或混入人工修改。

## 3. 增量 Wiki 整理

只有存在 Markdown 变化才调用 Codex：

1. 对非删除的变更笔记扫描疑似密钥，命中后停止。
2. 写入变更列表和提示词，以备份库为工作目录执行 Codex。
3. 提示词要求先读 `AGENTS.md`，只查看变更笔记和相关既有 Wiki，保留日期、来源、分歧与不确定性。
4. 返回后核对 AI 修改范围，只允许 `projects/`、`learning/`、`journal/`、`profile/`、`index.md`、`log.md`；越界则失败。

AI 不修改原始归档、维护规则、自动化代码、Git 和认证配置。删除的来源按需标注，已有 Wiki 不自动删除。

当前模型、推理和沙箱参数见运行脚本；认证继续由本机用户的 Codex 配置管理。临时会话不等于服务端零留存保证。

## 4. 原始归档

无 Markdown 变化时同样运行归档；若前面的模型调用失败，则不会继续本轮归档。

- 按原目录结构把可收录文件写入 `原始笔记/`。
- 通过 SHA-256 比较，只复制新增或变化的文件。
- 保留目标独有的旧文件，不做删除同步；改名后可能保留新旧两份。
- 排除 `.obsidian/`、嵌套 `.git/`、`.DS_Store`、匹配规则的凭据/私钥文件名和被识别为重解析点的文件。
- 对准备复制的指定文本扩展名文件扫描疑似密钥；当前脚本对匹配 `_test.` 的文件名跳过这层文本扫描。
- 源库嵌套 `.gitignore` 不控制收录范围；归档目录使用强制暂存。

过滤和正则扫描不能识别所有私人或工作资料。目标保持私有也不代表适合收录任何内容；部署者应先检查源库范围。

## 5. 提交、推送与清单推进

归档结束后写入临时清单，暂存原始归档、Wiki 和存在的导航文件。检查非原始归档变更的空白错误，并扫描索引、维护日志和四个 Wiki 目录的暂存差异。

有变化则创建提交；无变化则跳过提交。两种情况都尝试 `git push origin main`。只有推送成功才将临时清单替换为正式清单，避免把失败轮次误标为已处理。

异常会记入日志并清理锁，但不会自动撤销已经生成的文件、复制的归档或本地提交。下次运行前需要检查现场；强制结束进程可能留下锁。

## 6. 状态文件与核验

默认状态目录 `.local-state/` 被公共模板的 `.gitignore` 排除：

| 文件 | 作用 |
| --- | --- |
| `config.json` | 本机路径配置 |
| `source-manifest.json` | 最近成功推送后的 Markdown 清单 |
| `pending-manifest.json` | 当前轮临时清单 |
| `changed-sources.json` | 最近一次有 Markdown 变更时的列表 |
| `prompt.txt` | 最近一次生成的整理提示词 |
| `logs/nightly.log` | 完成数量与失败原因 |
| `lock/` | 重叠运行保护 |

日志出现 `Run completed and pushed` 才表示本轮完成。没有新提交可能只是资料未变化；任务启用或 `Ready` 不能证明推送成功。

```powershell
Get-Content -LiteralPath '.local-state\logs\nightly.log' -Tail 40
# 对私有备份库执行；路径为示例：
git -C 'C:\Notes\MyPrivateWiki' status --short
git -C 'C:\Notes\MyPrivateWiki' fetch origin
git -C 'C:\Notes\MyPrivateWiki' rev-list --left-right --count HEAD...origin/main
```

输出 `0 0` 表示本地与刚获取的远端 `main` 提交一致；仍应结合本轮日志判断同步结果。

## 7. 故障排查

| 问题 | 处理方法 |
| --- | --- |
| 无法确认目标私有 | 检查 `gh` 登录、目标访问权限及 `origin`；不要把公共模板当作备份库 |
| 找不到 Codex | 应用升级可能改变 CLI 路径；定位实际程序并更新本机配置 |
| 有本地修改 | 查看差异，核实后提交或另行保存，再执行自动任务 |
| 锁存在 | 检查是否有运行中的任务；确认无实例后再处理遗留锁 |
| 疑似密钥命中 | 人工核对对应文件及收录范围，处理后重新执行 |
| AI 修改越界 | 检查保留的差异并纠正；任务失败不等于改动已回滚 |
| 推送失败 | 检查网络、认证、权限及远端新提交；先获取并核对，避免强推 |
| 找不到日志 | 先查配置、路径与任务执行账户；部分启动错误发生在日志建立前 |

## 8. 公开版本的范围

本模板从通用脚本和空白文档重新建立 Git 历史；不包含原笔记副本、项目摘要、履历、个人时间线、截图、附件、实际状态文件或旧部署记录。历史平台脚本未纳入公开版，当前提供 Windows 实现。
